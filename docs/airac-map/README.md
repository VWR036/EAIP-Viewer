# AIRAC 地图功能实施指南

本文是交给后续 agent 的实现任务说明，尚未代表功能已完成。目标是在现有 AIRAC 模块中，用 Leaflet 实现可搜索、可点击的“指定点＋导航设施＋航路＋机场”地图。

## 1. 任务范围与约束

- 使用 Vue 3、现有 Ant Design Vue 控件及 Leaflet；仅增加必要的 `leaflet` 依赖，不引入 Vue 地图包装库、后端或其他 UI 框架。
- 地图作为 AIRAC 模块内部的视图，与现有数据浏览视图切换；不新增主导航模块，不改变机场航图、EAIP 资料功能。
- 保留现有 AIRAC 树、属性、关联对象、来源 XML 和数据检查功能。
- 遵守用户提供的 AGENTS.md：最小改动、沿用样式、错误明确、不增加无必要的兜底逻辑。
- 不运行 `npm run build`、`yarn build` 或其他生产构建，除非用户另行明确要求。
- 不提交原始 Dataset、生成索引、瓦片缓存或 node_modules。不要覆盖工作区已有用户改动。
- 本次仅实现四类数据；空域、跑道几何、三维、编辑、实时航迹、离线瓦片及 Difference 合并不在范围内。

## 4. 复用现有数据加载

当前加载链：

```text
public/data/airac-index/manifest.json
  ├─ objectsFile   → <generation>/objects.json
  └─ relationsFile → <generation>/relations.json
```

- 使用 `loadAirac()` 及 `airac.objects`、`airac.relations`、`airac.manifest`，不重复 fetch 整套数据。
- 不修改 BASELINE 时间片选择规则；只绘制 `active === true` 的对象及关系。
- 对象结构为 `{ id, type, fields, properties, active, ... }`。
- `properties` 是节点树；每个节点有 `name`、`namespace`、`attributes`、`text`、`children`。
- `fields` 主要是平铺的简单属性，坐标位于 `properties` 的嵌套节点中，不在 `fields.lat/lon`。
- 引用记录包含 `sourceId`、`targetId`、`field`、`path`、`role`、`active`。关系图为全量来源，`relations.airports` 只是机场关联聚合，不能代替全量航路网络。
- 已加载状态必须复用；索引加载错误沿用现有错误提示，不显示为空地图掩盖错误。

## 5. 坐标提取规则

按对象语义路径提取，不要递归找到任意第一个 `pos` 就使用：

| 类型 | 目标路径（省略时间片根节点） |
|---|---|
| 机场 | `ARP / ElevatedPoint / gml:pos` |
| 指定点 | `location / Point / gml:pos` |
| Navaid | `location / ElevatedPoint / gml:pos` |

以上是当前已见结构；实现前核查全量数据中的几何结构和 CRS。只有确认的数据结构才应支持，不猜测未知路径的含义。

- 检查 AIXM/GML 命名空间，读取几何节点上的 `srsName`。
- 当前已见 `urn:ogc:def:crs:EPSG::4326`，`pos` 顺序为 **纬度、经度**，单位为十进制度。
- Leaflet 的 `LatLng` 接受 `[纬度, 经度]`；GeoJSON 接受 `[经度, 纬度]`。明确区分转换边界，禁止二次颠倒。
- 例如原始 `29.0855555555 119.6202777778` 应生成 GeoJSON `[119.6202777778, 29.0855555555]`。
- `xsi:nil="true"`、缺少位置、空 `pos` 表示位置不可用，排除绘制并计入诊断。不生成 `[0,0]`、机场中心或邻近设施等替代位置。
- 非空但格式错误、非有限数值、越界坐标、未知 CRS 或不支持的几何结构应明确报告对象 ID 与原因；不要默认为 EPSG:4326 或自动交换轴。
- 诊断在界面可查看：各类已绘制数、缺失位置数、无效位置及不可绘制航段。合法缺失与数据错误分别呈现，不使用空 `catch`。
- Navaid 坐标代表设施整体。不得宣称它就是关联的每个设备的独立测量坐标。

## 6. 航路与航段构造

```text
RouteSegment --routeFormed--> Route
RouteSegment --start / pointChoice_fixDesignatedPoint--> DesignatedPoint
RouteSegment --end   / pointChoice_navaidSystem-------> Navaid
```

起点和终点均可能引用指定点或 Navaid，不能把上图示例当作固定端点类型。

1. 一次遍历有效引用，建立航段起终点、所属航路、航路到航段及 Navaid 到设备的索引。
2. 端点引用使用 `field` 为 `pointChoice_fixDesignatedPoint` 或 `pointChoice_navaidSystem`，并通过 `role` 的 `start` / `end` 区分。
3. 每个可绘制航段创建一个 GeoJSON `LineString`，坐标为 `[起点经纬度, 终点经纬度]`。
4. 两端必须均可定位；缺失、异常或歧义关系应明确报告。不能跨过缺失点直接连接后续点。
5. 由 `routeFormed` 归属航路，保留航段 ID、航路 ID、端点 ID；使用 `label()` 生成航路名称。
6. 一个航路可能断开或分支。高亮其真实航段集合，不按名称、经度、JSON 顺序或 ID 顺序拼成一条折线。
7. 点击共享/重叠航段时，应能访问该位置的其他航段及航路，避免最上层线永久遮挡下层数据；可用命中候选列表实现。
8. 直线连接仅表达航段端点关系，不推导程序转弯、弧线、实际飞行轨迹或可飞方向。需要显示方向时，另外读取并确认原始方向字段。

## 7. 界面与交互要求

- 在 AIRAC 内提供“数据浏览 / 地图”切换，使用现有 Ant Design Vue 控件。状态放在 AIRAC 本地，避免影响其他模块。
- 地图视图提供四个图层开关：机场、指定点、导航设施、航路；默认开启。搜索定位隐藏图层中的对象时，应同步开启对应图层。
- 初始视野根据有效要素计算范围，包含点与航段；不固定某个机场，也不每次点击后重置全图。
- 地图搜索独立于现有机场树搜索，支持机场 ICAO/IATA/名称、指定点代码/名称、Navaid 代码/名称、航路编号；忽略大小写及首尾空格。
- 重名结果显示类型、代码、名称，用 ID 区分；限制显示的结果数，并提示有更多结果，不悄悄丢弃匹配项。
- 定位点时居中放大并高亮；定位航路时缩放至其全部可绘制航段范围。无位置对象应显示不可定位原因，不伪造位置。
- 点击点/线显示名称、类型、对象 ID 及对应关键属性；航段显示所属航路、起终点、长度和磁航迹，单位沿用原数据。
- 提供“查看数据详情”，复用 `openObject(id)` 并切换回数据浏览视图。地图切回时尽量保留中心、缩放与图层选择。
- 点击航路或航路搜索结果高亮其全部航段；点击设施可查看关联设备，并进入设备详情。
- 初始只显示必要标签；放大后显示更多点名，避免全国范围文字重叠。不默认对全部点调用永久 Tooltip。
- 控件遵循 `--panel`、`--text`、`--dim`、`--line`、`--accent` 等现有主题变量；复用现有错误和空状态样式。
- 使用原生 Leaflet 提供的地图交互；弹窗中的外部数据使用文本节点或 Vue 安全插值，不拼接未转义的 HTML。

## 8. 地图库、底图与性能

- 添加 `leaflet` 依赖及其 CSS；随代码更新 lockfile。点使用 Canvas CircleMarker，线使用 Canvas Path；避免数千个 DOM Marker。
- 推荐以 GeoJSON 作为派生数据格式。一次生成并复用特征与关系索引，避免每次搜索或点击遍历完整 XML/属性树。
- 不将 Leaflet 实例放入深层响应式对象；使用局部实例或 shallow 引用。
- 在 `onMounted` 后初始化；容器必须有实际高度。地图切换显示或容器尺寸变化后调用 `invalidateSize()`；销毁时移除地图、监听器及观察器。
- 地图使用 AIRAC 已加载的数据，不引入全局重构，也不为首版新增服务端索引或瓦片服务。
- 首版可用 OSM 标准栅格底图 `https://tile.openstreetmap.org/{z}/{x}/{y}.png`，保留可见的 `© OpenStreetMap contributors` 署名及链接。
- OSM 公共瓦片用于开发和轻量访问；上线前按实际用途核对瓦片使用政策，正式高流量部署另选供应商或自托管。禁止批量预取和离线下载。
- 参考：[Leaflet](https://leafletjs.com/)、[OSM 瓦片政策](https://operations.osmfoundation.org/policies/tiles/)。
- EPSG:4326 数据交给 Leaflet，由地图库投影到默认 EPSG:3857。不要手动把经纬度当作平面米坐标。
- OSM 底图无需 GCJ-02 转换；本阶段不使用高德/百度底图，不引入坐标偏移算法。
- 网络或瓦片失败应有明确提示；不自动切换未配置的服务。已加载的 AIRAC 覆盖层仍应可交互。
- 首版深浅色主题作用于控件和覆盖层，允许沿用同一 OSM 底图；不要用整体颜色反转影响地图语义。

执行步骤：

1. 核对当前索引和代码；统计四类对象的有效几何、CRS、缺失值及引用结构。
2. 先实现数据转换与诊断，独立验证坐标顺序和航段端点，不先堆积 UI。
3. 接入 Leaflet，先绘制四层，再增加开关、搜索、弹窗、高亮及详情跳转。
4. 检查生命周期、深浅色主题、布局尺寸、错误展示和既有模块回归。
5. 补充相关说明，报告实际绘制数、排除原因、验证结果及剩余限制。

无需为了地图重写索引格式或修改原始 Dataset。若现有字段确实不足，先明确具体缺口，再做必要的小范围索引改动，并保留现有校验及发布语义。

## 10. 验证与完成标准

数据转换逻辑值得添加精简的测试，使用项目现有工具或 Node 内置测试能力，不为此新增测试框架。覆盖：

- 已知坐标的轴顺序正确，机场 ARP 提取正确。
- nil、空值、错误数值、越界和未知 CRS 按明确规则诊断；不会生成假坐标。
- 仅使用有效对象和有效关系；不把设备重复画成 Navaid 标记。
- 指定点/Navaid 混合端点解析正确，缺失端点不连线。
- 断开、分支航路及共享端点保持真实拓扑，不误拼接。
- 搜索处理同名、大小写、无位置对象，结果保留正确对象 ID。

使用 Vite 开发预览，执行相关纯函数测试与 Vue SFC 编译检查；如果改动索引脚本，运行现有 `test_airac_index.py`。未触及索引时不为地图重复生成约 79 MB 的对象索引，也不运行无关测试或生产构建。
